The problem

Deleting a tag is one click. Untangling it is a project.

Zendesk's own Tags page shows, in its own words, "the top 100 most used tags in the last two months". So the tag that has been sitting unused for a year is not on it — and the one that is quietly steering a trigger is easy to delete by accident.

Blind spot

You cannot see what is left

100 tags, 60 days. Everything beyond that — the long tail, the stale ones, the single-use ones — is invisible in the standard UI, so it accumulates.

Silent breakage

Rules keep pointing at tags you deleted

Triggers, automations, macros, views, SLA policies and ticket fields can all reference a tag. A rules-only view calls a tag "safe" that is not — and a broken rule fails quietly, in production, on a real ticket.

Duplicates

Spelling drift splits your data

Typo, case and separator variants — vipcustomer, Vip Customer, vip-customer — look like three tags and report like three. Counts split, rules miss, dashboards lie a little.

Bulk is the danger

The bigger the cleanup, the higher the stakes

Renaming 40 tags across thousands of tickets is exactly when a constraint — a tag too long, an invalid character, a reference you missed — costs you the most. You need the whole picture in one place, before anything runs.

How it works

Inspect. See the references. Change safely.

  1. Scan the full inventory

    Tag Janitor reads every ticket through the incremental export — not the top 100 of 60 days. You get a row per tag: ticket count, closed-ticket share, last use, and what the tag is used in.

  2. Read the reverse index

    Pick any trigger, automation, macro, view, SLA policy, ticket field or organization and see its tags — including ticket field values and organization tags. Pick any tag and see everything that references it.

  3. Change with a preview

    Rename, merge or delete in bulk, behind a dialog that states what will change and what Zendesk will reject — constraints like tag length and invalid characters — before anything runs.

Capabilities

Four views, one decision

Inventory

Every tag in the instance: ticket count, closed-ticket share, last use, and where it is referenced. The long tail included — no 100-tag or 60-day cap.

Reverse index

From rule to tags and from tag to rules. Triggers, automations, macros, views, SLA policies, ticket field values and organization tags — both directions.

Duplicates

Typo, case and separator variants clustered together, with their ticket counts, so you merge into the spelling your agents actually use.

Bulk rename, merge, delete

Apply changes across many tags at once — behind a preview that names what will change, what Zendesk will reject, and what to fix first.

Install

Three steps to a first scan

  1. Install Tag Janitor into your instance from the Zendesk Marketplace.
  2. Open the app from a support tab and run a scan. It reads tickets and rules through your own Zendesk session — nothing else.
  3. Read the inventory, check the reverse index, and apply only the changes you approve — each behind its preview.

In short

There is no onboarding, no key to exchange and no account to create before the first scan. The app reads, you review, you approve.

Access inside the instance follows your own Zendesk permissions. Pricing and terms of the Zendesk Marketplace apply.

FAQ

Questions, answered plainly

How is Tag Janitor different from Zendesk's own Tags page?

Zendesk's Tags page shows, in its own words, the top 100 most used tags in the last two months. Tag Janitor reads the full ticket inventory through the incremental export, so it is capped at neither 100 tags nor 60 days. On top of that it shows where every tag is still referenced by triggers, automations, macros, views, SLA policies, ticket fields and organizations — the reference check Zendesk's tags UI does not give you.

Does Tag Janitor send my helpdesk data anywhere?

No. The app has no backend, no account and no signup. It is pure HTML and JavaScript inside the Zendesk App Framework: every request goes through Zendesk's own framework client to your own Zendesk instance. No helpdesk data is transmitted to the publisher or to any third party.

What happens before a rename, merge or delete runs?

Every change runs behind a preview dialog. It states which tags will change and what happens to each of them, and it lists the Zendesk constraints that will reject parts of the operation — for example tag length limits or invalid characters — before anything is sent. Nothing runs without that confirmation.

Which tag variants does it find?

Tag Janitor clusters typo, case and separator variants of a tag together — for example 'vip-customer', 'Vip Customer' and 'vipcustomer' — so you can merge them into the spelling your agents actually use.

How does it know which rules reference a tag?

It reads the rule definitions from your own Zendesk instance — triggers, automations, macros, views, SLA policies, plus ticket field values and organization tags — and builds a reverse index from tag to the rules that use it. The check runs in your browser; no rule data leaves your instance.

Does the app track me?

No. The app contains no analytics, no tracking and no cookies of the publisher's. This public website is measured separately with a self-hosted, cookieless pageview counter that sends only a fixed page name and hostname; Do Not Track and Global Privacy Control stop it. Details in the privacy policy.

What plans and roles can use it?

Anyone with access to the Zendesk Marketplace can install Tag Janitor into their own Zendesk Support instance. Usage inside the instance is subject to your own Zendesk permissions: installing the app and running scans and changes require the access your Zendesk account grants for apps and tags. Pricing and terms of the Zendesk Marketplace apply.
